# Result

The unified renderer bounded-passes the intended separation:

```text
Sun moves continuously     → ARCnet presentation moves
Moon moves independently   → lunar tracer/phase changes
Vitae event absent         → Vitae coordinate remains fixed
explicit Vitae event       → Vitae coordinate changes once
later sky changes          → Vitae remains at the event-selected coordinate
```

The renderer also makes the typed-cell icosahedral bridge visible:

```text
shared icosahedron vertices / selected edges → Tempus carrier
shared icosahedron faces                     → Vitae corpus atlas
outer dodecahedron vertices                  → exact dual pointers to Vitae face slots
```

The dual pointer is deliberately drawn as a secondary line. It means only that one dodecahedral vertex and one icosahedral face are exact dual geometric elements.

It does **not** mean that the outer vertex acquires a Tempus state, that a zodiac sign selects the Vitae face, or that proximity/incidence creates readiness, curriculum dependency, recognition, or authority.

# Atlas placement boundary

The renderer supplies twenty deterministic display slots for the existing `10 Grades + 10 Specializations` count so the cell complex can be inspected.

The **placement orientation is renderer metadata only**. Existing Vitae doctrine does not ratify the geometric adjacencies, oppositions, or slot-neighborhoods produced by that placement.

Therefore:

- selected face = current corpus-region view;
- face adjacency = inert;
- face completion = not progress;
- outer dual vertex = pointer only;
- Sun/Moon position = never selects a Vitae face.

# Ephemeris posture

Production ephemeris ingestion remains separately provenance-bound and should use explicit observer/frame/epoch/source/version/precision metadata.
