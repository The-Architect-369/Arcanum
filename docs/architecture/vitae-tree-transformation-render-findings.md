# 1. Carrier and operator separate cleanly

The earlier harmonic render used a replaceable circle-of-fifths pitch sequence to make traversal order audible.

The new render separates two questions:

```text
CARRIER
what pitch material is sounding?

OPERATOR
what transformation is occurring between source and destination?
```

The operator is derived from presentation geometry:

```text
vertical displacement
→ frequency glide

horizontal displacement
→ stereo movement

diagonal displacement
→ frequency glide + stereo movement
```

Two carrier modes are provided:

```text
fixed 220 Hz carrier
→ isolates the operator

circle-of-fifths carrier
→ tests whether the same operator remains perceptible while pitch material changes
```

Candidate law:

> **Carrier Is Not Operator — changing the pitch carrier must not change path identity.**

This is a stronger architecture than assigning a permanent note to each sefirah or Hebrew letter because the sound consumes the existing relationship rather than creating it.

# 6. A balanced lateral weave appears

Using the presentation coordinates:

```text
left   = -1
center =  0
right  = +1
```

The nine transition vectors are:

```text
Malkuth  → Yesod     ( 0, -1)
Yesod    → Hod       (+1, -1)
Hod      → Netzach   (-2,  0)
Netzach  → Tiferet   (+1, -1)
Tiferet  → Gevurah   (+1, -1)
Gevurah  → Chesed    (-2,  0)
Chesed   → Binah     (+2, -1)
Binah    → Chokhmah  (-2,  0)
Chokhmah → Keter     (+1, -1)
```

Summed by path class:

```text
horizontal / Mother-class dx = -6
diagonal   / Simple-class dx = +6
vertical   / Double-class dx =  0
```

Therefore:

```text
net dx = 0
net dy = -6
```

The path ascends six presentation levels while returning to the center axis with zero net lateral drift.

Mirroring the Tree reverses the signs:

```text
horizontal = +6
diagonal   = -6
```

but preserves equal magnitude and zero net lateral drift.

So the strongest invariant is not left-versus-right direction. It is:

> **opposing lateral movement balances while ascent accumulates.**

Candidate law:

> **Mirror Without Meaning Loss — presentation handedness may reverse while typed relations remain intact.**

# 7. The balance depends materially on the full-width Lurianic diagonal

The five selected diagonal lateral movements have magnitudes:

This is a legitimate rendered relationship worth preserving.

It is not evidence that the historical tradition encoded this auditory or vector balance intentionally.

Candidate law:

> **Rendered Symmetry Is Evidence for Design Study, Not Historical Intention.**

# 9. What has not yet been tested

This prototype defines and renders the operators but does not constitute a human listening study.

Not yet established:

- whether listeners can reliably distinguish V/H/D without labels;
- whether the fixed carrier produces clearer operator perception than the fifths carrier;
- whether full stereo spatialization is comfortable or accessible;
- whether Mother-class crossings are actually heard as phrase boundaries;
- whether the Lurianic full-field diagonal is perceptually salient without visual context;
- whether any operator should use a perfect fifth rather than another neutral upward interval;
- whether timbre should carry any historical articulation metadata.

# 10. Next gate

The next bounded render should add the five historically sourced articulation groups as **optional timbre/phonation families** while keeping them independent of Vitae's five Spirit/Air/Fire/Earth/Water section semantics.

The test should compare:

```text
Tree path class
= transformation geometry

letter articulation group
= optional voice/timbre characteristic

carrier
= replaceable pitch material
```

These must remain separate dimensions.

A useful experiment would be a small matrix in which the same V/H/D operator is replayed with each of the five articulation-derived timbre families. If path identity survives timbre substitution, then the architecture gains a second independent perceptual axis without confusing the two registries.

Only after that should Tempus phase be introduced into the live render.
