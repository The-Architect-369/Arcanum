# Governance Lifecycle

Status: canonical-draft

## Purpose

Defines the formal lifecycle for shared binding governance, treasury, protocol, application, and continuity actions. Independent private creation and non-binding drafting outside system Architect tools do not require entry into this formal lifecycle.

System Architect tool eligibility requires the applicable Vitae stage and separately reviewed bounded permissions. Exact stage-to-tool ordering and unlocks remain deferred; existing draft associations do not activate permissions. See the [decision and readiness record](architectgpt/decision-review-20261011.md).

## Lifecycle

1. Draft
2. Sponsorship
3. Review
4. Governance Vote
5. Timelock
6. Execution
7. Receipt

### Draft
Minimum eligibility: V2 Steward Candidate.
Creates a non-binding proposal within this draft formal workflow; this candidate eligibility association does not restrict independent private drafting or establish an approved tool unlock.

### Sponsorship
Minimum eligibility: V3 Module Steward.
Moves a proposal into formal review.

### Review
Performed by the appropriate council.
Review evaluates but does not approve.

### Governance Vote
Binding governance participation by eligible governance stewards.

### Timelock
Required before execution.
Suggested ranges:
- Minor: 24h
- Treasury: 72h
- Protocol: 7d
- Constitutional: 14–30d

### Execution
Separate from voting.
Must occur through approved execution pathways.

### Receipt
ARCnet records factual governance events only.

## Treasury Flow
Draft → Sponsor → Treasury Review → Vote → Timelock → Execute → Receipt

## Protocol Flow
Draft → Review → Testing → Vote → Timelock → Upgrade → Receipt

## Constitutional Rule
Shared binding proposals must follow the applicable review, governance, timelock, and receipt requirements of their controlling documents, including only separately authorized emergency paths. This rule does not apply those formal steps to independent private drafting or create new emergency exceptions.
